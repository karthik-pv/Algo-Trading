## 1. What the 2PMM is

Mines **when 3O comes up** — the 30m VOC crossing above zero (`3OX-up`, detected on a
5m close) — plus coincident `5OX-up` events, with the full state/level/run context of
each event, to forecast and capture price swings (Swing / Intra / Scalp).

## 2. The engine — `forecasting/pmmEngine.py` (new)

Stdlib-only, house-style. Run (zero tokens, seconds):

```
python3 -m forecasting.pmmEngine                                 # full rebuild
python3 -m forecasting.pmmEngine --from 2026-01-01 --to 2026-10-23
python3 -m forecasting.pmmEngine --out PATH
```

- **Grain**: one row per 3OX-up; a 5OX-up in the same 30m window pairs into that row's
  5O block (nearest unpaired wins, max one per row); extra 5OX-ups get their own rows;
  no-event days get one record (state as of 15:25). Records ordered by primary event
  time, `record_no` 1-based per day.
- **Columns (48)**: `date, record_no, 3o, 3o_time, 3o_mderun, 3o_slevels, 3o_rlevels,
  3o_crossed, 3o_synchers, 3o_uprun, 3o_downrun, gap, 5o … 5o_crossed, 5o_synchers,
  5o_uprun, 5o_downrun, 3s, 3sz, 3sn, 3p, 3pn, 3m1, 3m2, 3ov, 3on, 2s … 2on, ds … don`
  — see the docstring for every definition.
- **State cells (2026-10-25)**: MACD cells are `X_n` / `Y_n` with n UNSIGNED (Y already
  means below zero; `abs(age)` in `xyn` — was `Y_-5`, now `Y_5`). PVT values (3p/2p/dp)
  print 1 decimal. `3ov`/`3on` = the carried 30m VOC value + its 30m-bucket age,
  displayed as `3o`/`3on` (the CSV name is `3ov` — `3o` is taken by the event flag);
  fed by the dense display copy `voc3d`/`vocs_3d` (raw sparse `voc3` still drives
  event detection).
- **Levels**: the >=1E100 ladder (1E100/1E200/3E50/3E100/5E50/5E100/5E200) + VWAP +
  Round100s + PDH/PDL/PDC/PDOpen (HA prev day) + ORH/ORL + D/W/M PSR pivots (house HA
  formulas). **Both event blocks are positional (2026-10-25):** `<prefix>o_slevels`/
  `<prefix>o_rlevels` = the single ladder level bracketing the event close at that
  block's own print (nearest at/below / nearest above, '+' joins confluence);
  `<prefix>o_crossed` ("Levels Crossed") = the rest of the ladder the run legs swept —
  up-side `(close, close+uprun]` nearest-first, then `|`, then down-side
  `[close-downrun, close)` descending. (The old interaction-catalog scan_levels was
  removed.)
- **Uprun/Downrun** via the 1E50 proxy = 5m EMA10 (span-match). Event below the rung →
  Uprun 0 + Downrun = the fall from the event close. No break by 15:25 → Uprun to EOD,
  Downrun NA.
- **RL Levels (revised 2026-10-26, hybrid)** — the distinct ladder levels the session
  REJECTED from open through the event candle (high reaches the rung, the candle closes
  below it), highest first; the ladder adds `3E200` + `2HE50`. A parallel agent's
  rewrite (landed the same morning) had replaced the whole run model with
  cycle-endpoint SL/RL/URun/DRun — settled the same day as the HYBRID: the
  rejection-window RL kept + positional SL restored, and — at the user's call after
  review — the run columns switched BACK to the parallel agent's one-direction model
  (URun only when price went up, DRun only when it fell, signed support−resistance;
  no completed MACD2 move after the event → both blank, ~249/349 3O rows). The locked
  1E50-proxy run_points was withdrawn again — the 41.7 spot value in §3 applied to
  that withdrawn model only.
- **Synchers** (±3 on each one's own grid, `5PX-U`/`5PX-D` encoding): 5PX/5M1X/5M2X
  (5m rows), 3PX/3M1X/3M2X (30m buckets), 2PX (2H), DPX (sessions), 1PMX (1m bars,
  from 2026-08-03 only; 21 hits so far). 5M1X computed from the 5m closes.
- **Ages**: signed bucket counts (+n up / -n down, 0 = current bucket); MACD states
  `X_n`/`Y_n`; zones OSZ/NOSZ/MZ/NOBZ/OBZ. 2S/DS from the 30m export (the 5m file has
  no 2H/D Stoch); everything else from the 5m file.

**Output**: `data/insight/csv/2pmm_matrix.csv`.

- End-to-end spot check (2025-09-16): the 3O cross at 14:30, the 5O pairing at 14:20

  cross ≠ price strength — a mining dimension by itself).

## 4. DATA-SHAPE discoveries (conventions for future modules)

- **The 5m export's HTF study blocks are SPARSE, not carried**: 30m Stoch/MACD and the
  2H VOC + D MACD/VOC blocks print only on their update rows (82–99% empty); PVTs, the
  5m block and VWAP arrive dense. The engine forward-fills the sparse blocks before
  computing states (`load_5m`, `ff_keys`).
- **30m studies print on the :10/:40 rows** — INSIDE the closing window's bucket, not
  on the :15/:45 boundary (re-confirmed). Flip/age logic therefore fires on the *print
  row* (`bucket_ages`/`flip_events`) and measures age in buckets from the print's
  containing bucket. Cross candle counts as 1.
- The `1m EMA100/200` rungs (1E100/1E200 levels) only populate from 2026-07-13 (TV 1m
  history limit) — those level interactions are absent before, by design.

## 5. The 2PMM Grid tab (Flask app)

- Route **`/2pmm`** (+ `/2pmm/data`, mtime-cached like SPATT) in `server.py`; tab link
  in `templates/base.html`; panel `panel-2pmm` in `templates/app.html`.
- Renders the matrix client-side (1.1k rows x 48 cols fine). **Every column is
  sortable and filterable**: the filter row under the headers gives each column a live
  text filter (type → instant filtering on the displayed value), or a **checkbox
  picker** (the `All ▾` button) when the column holds ≤ 8 distinct values (event
  flags, MR/DR/ER, zones — except `3sz`, which uses the dropdown below). The 30m
  state columns (`3sz, 3sn, 3p, 3m1, 3m2, 3ov, 3on`) have a **quick-filter dropdown
  stacked under the text filter** (`DDSPEC`): zones list their values; sign columns
  offer `≥0` / `<0` (UT/DT); MACD cells offer `X ≥0` / `Y <0`. New dropdown options
  must stay compact — the selects size to their (narrow) column. Default sort
  **Date newest-first**; click any header to
  re-sort (click again flips direction; empties always last).
- Display conventions: Date `DD-MON-YY` (sorts by the raw ISO value), `No.` for
  record_no, `Gap` sits next to `No.`, the merged event block drops its prefix
  (O / Time / Run / SL Levels / RL Levels / **Levels Crossed** / Synchers / URun / DRun),
  URun/DRun shown as whole
  points. Centered group header row: Session | O · VOC up |
  30m | 2H | Daily. **Rows band by date** (dark `#1d1d21` / `#25252b`; whitish-gray
  banding was tried and reverted at the user's request — don't re-suggest it),
  the active event block is tinted, date + No. columns are sticky, prominent
  scrollbars. Column widths are content-driven like v1 — the filter widgets are
  absolutely positioned inside their sticky `th` so they never force a column
  wider. **Level column widths (user-dictated)**: SL Levels / RL Levels 360px
  (`td.lvq`), Levels Crossed 240px (`td.lvc`), Synchers 300px (`td.lv`); long
  cells ellipsize with a hover tooltip.
- **Merged event block (2026-10-26)**: the 3O/5O columns are ONE set of display
  columns (`ev, ev_time, ev_mderun, ev_slevels, ev_rlevels, ev_crossed,
  ev_synchers, ev_uprun, ev_downrun`); `resolveRows()` picks each row's own event
  at load (3O rows → 3o* fields, 5O-only rows → 5o* fields). The **O column is a
  3o / 5o / All select, default 3o** (349 / 802 / 1151 rows). Paired rows show as
  3O rows — their 5O rider stays in the CSV (the CSV itself is untouched).
- **Level cells are NAME-ONLY tokens (2026-10-26)**: no Nifty price, no time —
  e.g. `PDH+ORH`, `D-S2,R100|VWAP`. The R100 label dropped its price
  (`R100-25300` → `R100`); repeated tokens dedupe across the whole crossed cell
  (up-side first). **The Date column also has a date picker**
  (`<input type="date">` stacked under its text filter, exact raw-ISO match).
- The tab only *renders* the CSV — re-run the engine, hit Refresh.

## 6. Gotchas hit this session

- `server.py` line ~2001 has a nested-quote f-string that only parses on Python
  3.12+ — pre-existing in HEAD, fine under the venv; system python3 is 3.9 and
  CANNOT parse server.py (the engine itself is 3.9-compatible).
- `value_crosses(up_only=True)` — the matrix records up-crosses only; the raw
  down-cross counts (3O 349 dn / 5O 914 dn) stay available in the data.
- `run_points` guards events stamped after 15:25 (late 30m prints) — no session bars
  after the event → uprun 0 / downrun "".
