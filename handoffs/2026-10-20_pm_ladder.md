## 4. Deliverable — the indicator

`/Users/phvrao/Projects/TradingView/PM_Ladder_Table_v1.txt` (Pine v5, paste into
the Pine Editor). Table rows D/2H/30m/5m/1m/15s × columns TF | Trend | Expected
Price Action | Trade Case. Trend cell = LIVE PM state (developing values — the
actual current trend, what the chart shows); case cell = state machine on the
carried no-repaint values: Wait (pullback to rung zone, shows the top-rung price)
→ ARMED (price in zone, watching the PVT cross) → TAKE (PVT cross within ±3
trigger-TF bars; ✓M if MACD confirmed) → deep-in-zone warning. Row→layer map:
D=Swing(3E), 2H=Intra(5E), 30m=Intra(1E100/200), 5m=Scalp(1E9/21/50),
1m=scalp trigger status, 15s=Ultra. Instrument-agnostic — runs on BTCUSD too
(needs volume; index symbols without volume will show PVT flat).

**CORRECTION (2026-10-20, after first live test on Crude Oil):** the indicator
originally computed RAW cumulative PVT — wrong. The studies/exports/payload all
use the **PVT oscillator**: `vt = ta.cum(ta.change(close)/close[1]*volume)`;
`pvt = EMA(vt,3) − EMA(vt,10)` (kEma, pvt_short=3, pvt_long=10), then normalized
by the 25-bar max-abs (`pvt_shouldNormalize=true, pvt_normalizeLookback=25` — a
positive scaling, so signs/zero-crosses are identical without it). Source:
`NMF_ATM_OPTIONS_1PX_15O_5sPM_Alert.txt` lines 87-133 (`calc_pvt`, `maxAbs`,
`pvt_stats1`) — "Uptrending = PVT value > 0 AND MACD line above signal" (lines
144-147). The indicator now uses this oscillator; the CSV/validation were always
on it (the CSV PVT columns ARE the normalized oscillator). Lesson: raw cumulative
PVT sign ≠ the oscillator's sign — never substitute one for the other.
