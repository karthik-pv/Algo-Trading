## 1. What this is

TREPAT produces **chronological tracking commentary** in the unified SPATAM
vocabulary — S/R touches and retests, EMA/VWAP crossings, stochastic zone
crosses, momentor calls (`1PX UT`, `1M2X DT`, `1ox`, …), `5PZ` pre-calls,
`1PMX` swing starts, may-cross notes, price-action follow-through, and
`Expect 1PX_15PM` confirmations — in two modes:

1. **REPLAY (NIFTY):** post-session commentary from TradingView bar exports
   (1m primarily; 15s/5m optional) via `scripts/trepat_track.py` →
   `tv/spatam/Tracking_<date>.log` + the **trepat strip** Pine viewer
   (`tv/spatam/trepat.pine`, hover = read).
2. **LIVE (BTC):** TradingView alerts → webhook → **spoken** through the Algo
   app's TTS queue. Went live 2026-11-05 on a BTCUSD 15s chart.

**Vocabulary unification (2026-11-08/09 session):** LIVE (SPATAM) wording won
as the single dialect. `tv/spatam/Tracking_spatam` is now the **FINAL source of
truth** — both the SPATAM pine and `trepat_track.py` must follow its wording
exactly; neither side invents strings. (The old `tv/spatam/Tracking` guideline
is superseded.)

## 3. Replay engine — data requirements

Exports land in `~/Downloads` (pattern `NSE_NIFTY1!, <TF>_<hash>.csv` — pick
newest by mtime). Current run: **1m only** (`NSE_NIFTY1!, 1_bc27d.csv`,
Aug 27 → Nov 8), 15s/5m = None.

**Column mapping (2026-11-08 session):** TradingView exports now carry a
**descriptor row** (indicator names above the header row). The user's
descriptor row is authoritative; it is saved **positionally** in
`scripts/tv_export_columns.json` (171 headers + 34 descriptors from the
`1m Latest.numbers` template). On load: if the export's header row matches the
template exactly, the mapping is applied positionally — never by header-name
dict (generic names like `MACD Line` repeat). Log prints
`[map] header matches saved template — applied 34 canonical names`.

Template facts: 171 cols; indicator blocks per TF: MACD pair(s), `o` Plot
(VOC), `P` PVT (normalized ±1), zero-line Plot, Cross Up/Down flags, K/D (S).
1m: 1M2 only; 5m/2h/Daily: M1+M2; 30m: 3M1+3M2. Cols 0–121: OHLC, D/W/M/Q P/R
ladders + HA variants, VWAPs, EMA grid (1s–M).
5P PVT updates on the boundary row; 5m MACD stamps land one row BEFORE the
boundary → PX crosses and 5PM/Bias are evaluated every 1m row (ffilled MACD);
M2X/stoch stay on stamp rows.
MX events = MACD Line vs its OWN Signal Line (confirmed) — not M2-vs-M1.

Gotchas:
- Export headers have **duplicate/generic names** — positional mapping only
- `Cross Up/Cross Down` flag columns come out all-zero — derive crosses from
  sign changes directly
- Exports carry **no volume** in replay → VOC `o` momentors need the export's
  `o` Plot column (present in template; VOC cross-UP only)
- Pivot columns can be NaN on the first row of a day — take a later row
- **Engine paths are hardcoded in `__main__`** — update CSV filenames each day

## 5. The rules — see `Tracking_spatam` (authoritative)

Short form of what the engine implements (details/wording live in the catalog):

1. Session open: gap up/down in % (the only numeric value ever announced)
2. Level **names only** — never index price / level values
3. **Momentor notation** (user-fixed): `1M2X 1PX 5M1X 5M2X 5PX 3M2X 3PX 2M1X 2M2X 2PX DM1X DM2X DPX` + `UT/DT`; volume `o` momentors have NO UT/DT — cross-ups only, announced as `1ox/5ox/3ox/2ox/Dox` (cross-downs never announced)
4. **5PZ pre-call:** `Attention : 5PZ UT` / `5PZ DT` (replaces the old "5PX about to cross up/down.."); 5m PVT in ±0.1 of zero + 1m PVT/MACD2 agreement
5. **Expect pre-call:** `Expect 1PX_15PM DT/UT` only when 1m PVT is trending into the level AND within ±0.1 of the zero line
6. **1PMX swing start:** condition = (1m PVT downtrending AND 1m MACD2 crossed down) OR (1m MACD2 downtrending AND 1m PVT crossed down) OR both crossed down together; UT mirrors. Wording names the acting level: `1PMX UT Support @ <latest first-touch group>` / `1PMX DT Resistance @ ...`
7. **May-cross note** on first touch of major EMA clusters only, per PVT→EMA mapping: 3P→1E100/200, 2P→5E50/100/200, DP→30E50/100/200, WP→2E50/100/200, MP→DE50/100/200
8. Stochastic: zones only (OBZ/MZ/OSZ); 15s MACD2 never standalone; 15s VWAP crosses dropped (replay); 1m/5m candle VWAP crosses fire on TF closes; VWAP proximity warning once per direction per episode, direction = approach side
9. S/R touches for the full EMA grid `TOUCH_EMAS` (1m–M, EMA9/21/50/100/200, **excluding 1E9 and 1E21**; 1E21 keeps only its dedicated comes-below/retrace events), full pivot ladder (D/W/M/Q × P/R1–R3/S1–S3, dedup within 5 pts), VWAPs; same-tick touches grouped; retests need ~25 pts retreat; 3rd+ touch = "...again"
10. **Price-action follow-through** (major EMA50/100/200 clusters only) — armed ONLY when the level is announced as touched/retested; fires on an **AGGRESSIVE candle** (body ≥ 1.5× avg body of previous 5 bars) closing beyond the level, next bar onward, 15-bar validity, one fire per episode:
    `Price rises above 1E200` (support hold + aggressive bull candle) /
    `Price falls below 1E200` (resistance hold + aggressive bear candle).
    (Do NOT use the old "close above the interaction-zone high" trigger — it
    misses aggressive moves when a spike set the zone high far away; the
    13:08/13:11 NIFTY case on 2026-11-06 proved it.)
11. 1E50 cross announcements gated on 1m PVT agreement (above-cross needs 1P > 0, below-cross 1P < 0)
12. Retrace-to-EMA lines carry NO `Attention :` prefix — only the 1m EMA50 cross event needs it
13. 1PMX decoupled from EMA21 price-cross; `below21` kept only for 1E21 retrace lines
14. 10-minute Summary feature: built, then **removed** at user request — do not reintroduce

## 6. Live mode (BTC voice) — what's wired

Chain: TV alert → `POST /trading_view_webhook` (server.py:1467) →
`MSG:"ALERTS"` → `trader.process_spatam_alerts()` (trade_logic.py:8578) →
`queue_spatam_speech()` → voice loop. Persisted to
`data/logs/SPATAM/SPATAM_Alerts_<date>.txt`.

- No symbol filter in the voice path; SPATAM's `alertJsonOn` must be ON
  (default true since 2026-11-05.38) — OFF = silently dropped
- One live SPATAM alert at a time (NIFTY and BTC both active = double-fire)
- Payloads carry no `SYM` on DATA/LEVELS (only SPATAM's ALERTS do)
- Voice UI toggle: muted-at-startup is normal; messages while muted are DROPPED
